# H0007 readiness artifact

**Status: report only. H0007 has not been run.** This assesses whether the
data H0007 (`HYPOTHESES.md`, "Preliminary-observation bound violations near
settlement") needs now exists, at what quality, and what — if anything —
still blocks pre-registration and execution. Every number below is a
measured query result against the live database as of 2026-07-21, following
the Phase 7A candlestick backfill (`docs/adr/0007-price-ingestion.md`).

## Summary verdict

**Partially ready.** The two data-collection dependencies H0007's own
`HYPOTHESES.md` entry lists as "Required data" are both satisfied, several
comfortably better than the hypothesis originally assumed. The block is a
single small, well-scoped **feature/dataset-integration step** — not missing
data, not a new collection surface, and not in scope for Phase 7A (which was
explicitly instructed not to do feature engineering). See "What's actually
blocking" below.

## Price/quote data (measured)

- 804/804 settled markets backfilled (KXHIGHNY tmax: 402, KXLOWTNYC tmin:
  402); 761,475 one-minute candles; 0 duplicates; 0 API failures of any kind.
- Coverage report (`prices coverage`) against the resulting store:
  `markets_captured=804`, `markets_complete=804`, `markets_incomplete=0`,
  `markets_never_captured=0`, `likely_lost_to_retention=0`,
  `duplicate_row_count=0`. Candle timestamps span 2026-05-14 through
  2026-07-21 (67 distinct event dates).
- 12-ticker stratified live-API sample (oldest 2, newest 2, 6 random, 2
  flagged for sparse coverage) matched stored counts **exactly, 12/12** —
  the "database counts and report counts must agree exactly" check.
- Both traded price and quoted bid/ask are present per candle; a zero-volume
  (no-trade) period still carries full bid/ask quotes, correctly flagged via
  `data_quality_status`.

## Known gaps (measured, not estimated)

- **1 of 67 settlement days (2026-07-02, 12 markets)** has price data but no
  resolved settlement label — `settlement_label_status = "missing_source_data"`
  for those rows (`market_prices` dataset). This is a weather-observation gap
  for that specific date, not a price-ingestion gap; out of scope to fix here.
- **10 of 804 markets** (all `KXLOWTNYC` "between"-strike (`B`) contracts —
  illiquid, far off the realized range) have far fewer stored candles than
  their own observed span implies (as few as 45 candles across a multi-day
  window). Confirmed via live re-fetch that this is the API returning no
  candle at all for idle minutes on thin strikes, **not** a backfill defect —
  all 10 also matched their live counts exactly in the validation sample.
  This narrows the *effectively usable* intraday sample for illiquid strikes;
  any future experiment sizing by strike liquidity should read
  `markets_with_missing_intervals` rather than assume uniform density.
- **24 markets** are settlement-resolvable but not yet in the settled/priced
  population — confirmed these are simply today's and tomorrow's still-open
  markets (`status="active"`/`"initialized"`, no `result` yet), correctly
  excluded from a settled-market price backfill. Not a gap; will backfill
  automatically once they settle (`ops run`'s price sync loop).
- No future/settlement leakage: 0 rows in `market_prices` have a candle
  `period_end` after that market's `settlement_time` (checked directly).
- Sample size is a real, quantified limitation, not just a caveat: H0007's
  own pre-registered minimum is "≥60 settlement days"; we have 66-67. This
  clears the bar but leaves little headroom — the pre-registered decision
  rule ("bounded-side sellable mass ... on ≥5% of settlement days") needs
  roughly 3-4 qualifying days out of 66-67 to trigger "confirmed", which is a
  small-numbers regime worth being conservative about when interpreting a
  result either way.

## What's actually blocking

H0007's `HYPOTHESES.md` entry was pre-registered assuming the live 5-minute
snapshot collector (`market_snapshots`) would supply intraday market history,
and that F6/F7 (`market_weather` columns `best_yes_bid/ask_cents`,
`obs_value_known`/`obs_issuance_time_known`) would carry that history back
through the relevant settlement days. Measured directly: `market_snapshots`
currently holds 828 rows, **all from a single pass today (2026-07-21)** — the
live collector has never run continuously long enough to build up historical
intraday depth. F6/F7 as literally implemented therefore have effectively no
historical reach, independent of anything in this phase.

The new candlestick archive (`market_prices`, this phase) is the superior
substitute for the *price/quote* side — finer resolution (1-minute vs.
5-minute), full historical depth via backfill rather than only-since-collector-
started. But it does not yet have F6/F7's *as-of join* — a per-candle-timestamp
"what was the latest known preliminary observation at this moment" column,
analogous to `market_weather`'s existing `obs_value_known`/
`obs_issuance_time_known`, built instead over `market_prices`. That join is
straightforward (the same as-of-join primitive `market_weather` already
uses, applied to a new base frame) but is feature-engineering work, which
Phase 7A was explicitly instructed not to do.

**This is the one concrete blocker**, and it is small and well-understood —
not a data-collection gap, not a new API integration, not model work.

## On ASOS/METAR

The task brief that requested this readiness artifact asked what ASOS/METAR
fields remain needed. Re-reading H0007's own pre-registered design: it is
built entirely around **discrete NWS CLI issuance values and timestamps**
("preliminary CLI issuance times/values" — its own wording), not a continuous
instrument feed. That data already exists (5,148 observations, issuance-time
tracked, multiple same-day issuances confirmed for 134/134 station-days in
the price-backfilled window). **ASOS/METAR minute-level readings are not
required to run H0007 as pre-registered** — they would only become relevant
for a different, more granular hypothesis about continuous intraday
temperature (not proposed), and are correctly out of scope here.

## Recommended next milestone

Price coverage is sufficient and observation coverage is sufficient; the
blocker is the as-of join gap above, not further collection. Recommended
next step: a small, explicitly-scoped feature-engineering milestone (Phase 4,
`TASKS.md`) that builds the `market_prices`-based equivalent of
`obs_value_known`/`obs_issuance_time_known` (an as-of join, not a new data
source) — after which H0007 can be pre-registered for execution per
`RESEARCH.md`'s standard experiment protocol. Do not lower H0007's
pre-registered ≥60-day threshold to force an earlier run; 66-67 days already
clears it, narrowly.
